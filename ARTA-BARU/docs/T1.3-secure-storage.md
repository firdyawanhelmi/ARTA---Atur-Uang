# T1.3 — Secure Storage (13 Okt 2026, Status: BLOCKED)

## Keputusan teknologi
`expo-secure-store` (jalur SDK 57) untuk token/kredensial.
Alasan: Keystore-encrypted SharedPreferences (Android) / Keychain
kSecClassGenericPassword (iOS), store terisolasi per proyek — memenuhi
PRD (SecureStore Keychain/Keystore, bukan SQLite/prefs/log).
Sumber: docs.expo.dev/versions/v57.0.0/sdk/securestore (mod 20 Jul 2026).

## Aturan desain mengikat (dari docs resmi)
- API: `setItemAsync/getItemAsync/deleteItemAsync`; kunci alfanumerik
  `.-_`; logout = `deleteItemAsync` eksplisit (tanpa auto-wipe).
- `requireAuthentication` DILARANG untuk ARTA (memakai biometrik;
  PRD melarang PIN/biometrik). `keychainAccessible` default
  `WHEN_UNLOCKED` dipertahankan kecuali diputus lain.
- Android: TIDAK survive uninstall; Auto Backup wajib exclude
  SecureStore (default plugin `configureAndroidBackup:true`).
- iOS: SURVIVE reinstall (bundle ID sama) → alur logout/ganti-akun
  WAJIB hapus eksplisit agar token basi tak terbaca akun lain (B5).
- Batas ±2048 byte iOS untuk payload besar (token kecil, aman);
  kunci biometrik invalid saat biometrik berubah; butuh device nyata
  untuk uji biometrik (emulator tak cukup).
- SecureStore ≠ enkripsi SQLite: boleh simpan kunci DB kelak, tetapi
  klaim enkripsi butuh evaluasi terpisah (PRD).

## Bukti vs kriteria
- C1 (bukti via penyimpanan aman kompatibel): BLOCKED — butuh
  `npx expo install expo-secure-store` (izin belum ada) + runtime
  device (T1.4).
- C2 (no token di SQLite/AsyncStorage/log/file): PASS statis —
  grep: belum ada penyimpanan token di kode mana pun; aturan tercatat
  di sini. Penegakan runtime menyusul C1.
- C3 (Android + rencana iOS): PASS dokumentasi (bagian di atas).
